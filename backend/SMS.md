# Development SMS delivery with SMSpit

Phone OTPs are captured by a local SMSpit inbox through the existing BullMQ worker.
They are not sent to a phone or carrier. Email continues to use Mailpit.

## Start and stop

With Docker Desktop running, from the backend folder:

```sh
npm run sms:start
```

Open **http://localhost:4301** for the SMS inbox. The API is at
`http://127.0.0.1:4300`. The compose file pins the tested SMSpit image by digest,
binds both ports only to localhost and stores its SQLite inbox in a named Docker
volume, `nestjs-advance-sms_smspit-data`. The backend can run normally on your Mac.

```sh
npm run sms:stop
```

Stopping preserves the inbox volume. Starting restores it. The container restarts
with Docker unless explicitly stopped. SMSpit's own `NODE_ENV=production` serves
its bundled UI; this does not put the Nest application into production mode.

## Backend configuration

These development settings have been added to `.env`:

```dotenv
SMS_PROVIDER=smspit
SMSPIT_URL=http://127.0.0.1:4300
SMSPIT_PROJECT=default
SMSPIT_API_KEY=
SMS_FROM=NestShop
SMS_TIMEOUT_MS=10000
```

Restart the backend after changing `.env`. Register with a phone number in E.164
format, then open SMSpit and copy the received code. Phone OTP login uses the same
path. If both phone and email are supplied at registration, each contact still
requires its own verification: phone codes are in SMSpit, email codes in Mailpit.
Unknown/unverified contacts do not receive login OTP messages.

`default` is an automatically created SMSpit project. To use another project,
create it in SMSpit first, then set `SMSPIT_PROJECT`. `SMSPIT_URL` is the server base
URL, not `/api/messages`; the adapter appends that route. It also supports a reverse
proxy base path. If the Nest app later runs inside Docker, use the container network
hostname instead of `127.0.0.1` and adjust the app's configuration accordingly.

An optional `SMSPIT_API_KEY` is shared by the backend and the compose service.
The adapter sends `X-API-Key` when configured. After changing it, restart/recreate
SMSpit with `npm run sms:start` and restart Nest. Keep it in the ignored `.env`.

Without an explicit `SMS_PROVIDER`, development defaults to SMSpit. Tests default
to the existing JSON provider source. `SMS_PROVIDER=LOG` restores development phone
logging. `SMS_PROVIDER=configured` uses `phone` settings in `otp.config.json`.

## Worker behavior

The worker posts `{ to, from, message, project }` to `/api/messages`. The code is
generated by registration/login before enqueueing and is reused on retries. The
adapter never creates a different code. The queue skips expired/replaced/used
challenges and the adapter applies an HTTP timeout without logging phone numbers,
codes, API keys or provider response bodies.

Network failures, HTTP 408/429 and 5xx responses retry through BullMQ. Other 4xx
responses fail permanently; check project names and API keys. There is no silent
fallback to LOG if SMSpit is unavailable. HTTP success from the auth API means
**queued**; the inbox entry appears when the worker completes delivery.

SMSpit's documented send endpoint does not provide an idempotency contract.
At-least-once delivery can therefore produce duplicate inbox entries after an
ambiguous request failure, using the same OTP. A real provider adapter should use
the supplied job idempotency key where the provider supports it.

## Production and RCS

SMSpit and explicit LOG SMS delivery are rejected in production. Set
`SMS_PROVIDER=configured` and implement the selected real provider's adapter using
the existing configuration/handler boundary. The legacy external-provider branch
still returns 501 until that integration exists; pointing it at an arbitrary API
does not automatically implement a provider's request/authentication contract.

This implementation simulates SMS delivery only. It does not implement an RCS
agent, capability detection, real carrier delivery or delivery-status callbacks.

## Tests

```sh
npm test
npm run test:sms
```

`test:sms` requires local Redis and the running SMSpit compose service. It creates
a unique SMSpit project and Redis prefix, exercises real queued phone registration
and login, verifies single-use codes, and checks that unknown contacts produce no
message. It removes only its own project and queue data. `TEST_REDIS_URL`,
`TEST_SMSPIT_URL`, `TEST_SMSPIT_UI_URL` and `TEST_SMSPIT_API_KEY` can override the local test endpoints.
